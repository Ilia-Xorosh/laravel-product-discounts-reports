# Laravel Product Discounts Reports

**От итоговой скидки — до каждого действия над товаром.**

Необязательное дополнение к [основному пакету](https://github.com/Ilia-Xorosh/laravel-product-discounts).
Помогает увидеть, какая акция изменила корзину, какие условия сработали
и как получилась итоговая сумма.

[Установка](#установка-локально) · [Статусы и оплата](#статусы-и-оплата) ·
[Интерфейс](#интерфейс-статистики) · [Excel](#excel)

```mermaid
flowchart LR
    Calculation[Расчёт с GUID корзины] --> Snapshot[Сохранённый снимок]
    Snapshot --> Basket[Корзина: до / после]
    Basket --> Action[Акция]
    Action --> Doing[Действие и условие]
    Doing --> Product[Изменение каждого товара]
    Snapshot --> Export[Excel mini / max]
```

| Возможность | Для чего |
| --- | --- |
| Снимки правил | Видеть применённые условия после изменения исходной акции |
| Детализация | Раскрыть корзину → акцию → действие → товар |
| Общие фильтры | Получать согласованные итоги, список и выгрузки |
| Excel mini | Строка на акцию с количеством затронутых товаров |
| Excel max | Строка на изменение товара в конкретном действии |
| Защита оплаты | Сохранять снимок оплаченного заказа при новых запросах расчёта |

Локальная проверка: **8 интеграционных тестов**, включая реальные XLSX-файлы
и откат транзакции при ошибке. Дополнение хранит **последний расчёт корзины**,
а не журнал всех её пересчётов.

## О дополнении

Дополнительный пакет к `product-discounts/laravel-product-discounts`.
Сохраняет статистику корзин, снимки применённых акций и действий, изменения
каждого товара; предоставляет Blade-интерфейс, фильтры и Excel mini/max.
PHP 8.2+, Laravel 11/12; тестовое окружение — Laravel 12. Лицензия MIT.
Исходники опубликованы в GitHub. В Packagist пакет пока не зарегистрирован.

## Установка с GitHub

После выпуска тегов `v1.0.0` обоих пакетов:

```bash
composer config repositories.product-discounts vcs https://github.com/Ilia-Xorosh/laravel-product-discounts
composer config repositories.product-discounts-reports vcs https://github.com/Ilia-Xorosh/laravel-product-discounts-reports
composer require product-discounts/laravel-product-discounts-reports:^1.0 -W
php artisan vendor:publish --tag=product-discounts-reports-config
php artisan vendor:publish --tag=product-discounts-reports-migrations
php artisan migrate
```

Основной пакет установится как зависимость. При первой установке также
опубликуйте его конфигурацию и миграции, настройте каталог и права доступа.
Оба VCS-репозитория необходимо указать именно в приложении.

## Установка локально

Используйте **обновлённый основной пакет** из соседней папки:

```text
packages/
  laravel-product-discounts/
  laravel-product-discounts-reports/
```

В корневой `composer.json` приложения добавьте оба репозитория:

```json
"repositories": [
    {
        "type": "path",
        "url": "packages/laravel-product-discounts",
        "options": {"versions": {"product-discounts/laravel-product-discounts": "1.0.0"}}
    },
    {"type": "path", "url": "packages/laravel-product-discounts-reports"}
]
```

```bash
composer require product-discounts/laravel-product-discounts-reports:@dev -W
php artisan vendor:publish --tag=product-discounts-config
php artisan vendor:publish --tag=product-discounts-migrations
php artisan vendor:publish --tag=product-discounts-reports-config
php artisan vendor:publish --tag=product-discounts-reports-migrations
php artisan migrate
```

Если основные миграции уже публиковались, повторная публикация не нужна.
ServiceProvider обоих пакетов подключается через package discovery.
XLSX использует PhpSpreadsheet; Composer проверит необходимые PHP-расширения
(включая mbstring, zip, gd, XML). Библиотека Excel нужна только дополнению.
Репозитории из `composer.json` зависимого пакета Composer не наследует:
пока нет публикации, оба локальных пути задаются в приложении явно.
После выпуска стабильных тегов версия `1.0.0` в локальных настройках не нужна.

## Запись расчётов

Вызовите основной калькулятор с идентификатором корзины:

```php
$result = app(\ProductDiscounts\DiscountCalculator::class)->calculate(
    items: [['configurationId' => 'sku-1', 'quantity' => 2]],
    actions: app(\ProductDiscounts\ActionResolver::class)->resolve(),
    promocode: 'SALE10',
    basketGuid: $basket->uuid,
    orderFrom: 'site',
);
```

API основного пакета также принимает `basket_guid` и `order_from` в JSON.
**Приложение должно проверять принадлежность GUID текущему пользователю/магазину**
в своём endpoint/middleware либо передавать GUID только из серверного кода.
В дополнении одна общая таблица корзин: GUID должен быть уникален в пределах
всего приложения, включая магазины. Для разных заказов используйте разные GUID.

Калькулятор отправляет синхронное событие `ProductDiscounts\Events\CalculationCompleted`.
Дополнение сохраняет его транзакционно; без дополнения основной пакет
не пишет отчёты и не требует их таблиц. Без GUID отчёт не создаётся.
Настройка `product-discounts-reports.recording=false` отключает сохранение.

Сохраняется **последний расчёт каждой корзины**, а не журнал всех её пересчётов:
повторный вызов атомарно заменяет дерево акция → действие → товар.
Записываются также корзины без скидок; старые акции при нулевом пересчёте удаляются.
Снимки независимы от исходных моделей акций: редактирование/удаление правил
не меняет уже сохранённый снимок (до следующего пересчёта этой неоплаченной корзины).
Применёнными считаются действия, реально изменившие позиции. Если несколько
действий взаимно компенсировались, оба остаются в отчёте даже при нулевом итоге акции.
Корзинные изменения содержат распределение по всем изменённым товарам.
Денежные значения — целые копейки/центы, наценка даёт отрицательную скидку.

Запись выполняется синхронно, без очереди. Ошибка БД откатывает отчёт целиком
и передаётся вызывающему коду; успешный ответ не маскирует потерю статистики.
Опубликуйте и выполните миграции перед включением записи в рабочем приложении.

## Статусы и оплата

Из доверенного обработчика заказа/платёжного уведомления:

```php
app(\ProductDiscounts\Reports\BasketStatus::class)->update(
    basketGuid: $basket->uuid,
    status: 'paid',
    paidAt: now(),
);
```

Допустимые статусы: `new`, `paid`, `failed`, `refund`, `error`.
Статус и дата оплаты из клиентского запроса расчёта **не принимаются**.
Сначала запишите финальный расчёт, затем отметьте оплату. После `paid`/`refund`
новые расчёты не перезаписывают снимок; повторный статус `paid` не меняет
первую дату оплаты. Оплаченную/возвращённую корзину нельзя открыть заново
через этот сервис — для нового заказа создайте новый GUID.
Статистика не заменяет проверку оплаты, резервирование и хранение заказа.

## Интерфейс статистики

В `config/product-discounts-reports.php` установите `admin.enabled=true`.
По умолчанию применяются `web`, `auth`, `can:view-product-discount-reports`.
Определите Gate в приложении:

```php
Gate::define('view-product-discount-reports', fn ($user) => $user->is_admin === true);
```

Адрес: `/admin/product-discount-reports`. Ссылка на корзину открывает снимки
акций, действий и изменения товаров. Блоки раскрываются нативным `details`;
сторонний JavaScript не требуется. Интерфейс дополнения не зависит от включения
основной админки. При необходимости добавьте его ссылку в меню приложения.

Фильтры: дата расчёта или оплаты, начало/конец периода (включая весь последний
день), статус, GUID, источник, минимальная скидка, название акции/товара,
тип действия, применение, единица скидки, условие. Фильтры действий и товара
ищут одно и то же действие внутри подходящей акции. Итоги, список и обе выгрузки
используют один запрос фильтрации. Фильтр выбирает корзины целиком:
в деталях и Excel остаётся полное дерево выбранной корзины, включая другие действия.
Итоги считаются по корзинам, а не строкам товаров, поэтому суммы не дублируются.
Для выручки выбирайте `paid`; по умолчанию показаны все статусы.

```bash
php artisan vendor:publish --tag=product-discounts-reports-views
```

## Excel

- Mini: строка на акцию; количество товаров считается по уникальным ID внутри
  акции, без повторного сложения одного товара из нескольких действий.
- Max: строка на изменение товара в конкретном действии, со снимком условия
  и суммами до/после на каждом уровне.
- Корзины без акций тоже включаются. Повторные суммы корзины/акции/действия
  в последующих строках пустые, чтобы суммирование столбцов не дублировало итоги.
- GUID и названия записываются как текст, включая строки с `=`, чтобы исключить
  исполнение формул и сохранить ведущие нули.
- По умолчанию до 50000 строк данных (`export_max_rows`). При превышении
  уточните фильтры. XLSX формируется в памяти; подбирайте лимит под доступную память.

## Разработка

```bash
composer install
composer validate --strict
composer test
```

Для локальной разработки рядом должна лежать обновлённая папка основного пакета.
Composer зеркалирует её в `vendor`; после изменений основного пакета выполните
`composer update product-discounts/laravel-product-discounts`, чтобы обновить зеркало.
Тесты используют SQLite в памяти, проверяют интеграцию калькулятора, снимки,
пересчёты, оплату, откат транзакций, фильтры и реальные XLSX-файлы.
Исходное приложение, его база и старые таблицы не изменяются. Автоматического
переноса старых данных нет. Для удаления данных дополнения используйте откат
его миграции только после осознанного решения удалить статистику.

Публикуйте в отдельный репозиторий только эту папку, без `vendor`, `.env`
и логов. В CI задайте переменную репозитория `CORE_REPOSITORY` для основного
пакета, если его адрес отличается от `<owner>/laravel-product-discounts`.
Основной пакет нужно выпустить с событием расчёта до выпуска дополнения.
